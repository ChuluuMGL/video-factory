# 客户远程安装与接管

用于代客户部署或客户用自己的 Agent 接管已有项目。先读取客户私有交接记录；通用复盘见 `docs/product/CUSTOMER_DEPLOYMENT_LESSONS.md`，不要把别的客户记录当作当前配置。

## 先建立稳定操作路径

1. 核对客户电脑、服务器主机指纹、安装路径和已有服务；区分客户服务器与实施方测试机。已有 n8n 优先接入。仅有远程桌面连接不意味着可以重启服务器或替换系统组件。
2. 有授权 SSH 就优先使用 SSH/API 做检查和配置；ToDesk 用于必要的官方页面。键盘/粘贴动作后必须看到实际下一步，若没有变化，停止重复输入，改用客户本地 Agent 或一次明确的人工终端操作。
3. 临时登录使用专用公钥，私钥留在所属电脑，验证可信主机指纹后再连接。不关闭主机校验。客户自己的隧道密钥与实施方临时管理密钥分别记录，最后只撤销后者。
4. 修改前只读记录 OS/架构、已有进程、端口、磁盘、数据库/网站和服务管理方式。独立安装目录和 loopback 端口，不替换全局 Node/Python、不改原 Docker 配置、不全局清理容器。无法隔离时先提出具体迁移或替代方案。
5. n8n 本机入口用客户已验证的隧道/启动器。先验证服务器 readiness，再检查本机端口和隧道；启动器按其 shebang 执行，不能把 zsh 脚本当 sh。服务器存活不能证明客户浏览器入口可用。

## 凭据输入前先把问题问对

显示工具名称、用途、平台完整 API 地址、区域和模型。n8n API Key 用于导入/检查工作流，模型 Key 用于该供应商；App Secret 属于本项目飞书应用。权限/有效期按实际 API 与任务需求确定，不把某次安装的权限数量套给所有客户。

优先客户私有终端隐藏输入，复用原项目已保存凭据。输入超时、缺字符、格式不合法与供应商 401 是不同问题；不能都说成“复制错了”。先查平台控制台地址和官方/供应商文档，再做只读认证；禁止把同一 Key 发到猜测的多个域名。响应不跟随跨域重定向，错误输出脱敏；Key 更新失败保留旧配置。没有安全输入能力时停在明确提示，不让客户将秘密发到聊天。

凭据存 n8n 加密库或安装器受控配置。私有交接只写存储位置、用途、保管人和到期日，不写值。辅助加密副本不等于自动完成备份与轮换；验收后按客户约定处理。

## 飞书身份与事件分别核验

- 查询邮箱成功但没有用户 ID，仍是身份未解析。核对组织、应用可用范围和企业资料；可用本应用官方人员选择器取得准确身份，不能按同名猜测或未经授权扩大通讯录范围。
- Base 权限、schema、订阅状态、已发布事件、长连接状态、程序事件、客户本人事件逐层检查。程序事件只能证明通道，不能充当费用负责人确认。
- 本安装路线需要的应用/用户身份权限以当前产品说明和官方错误为准；增加权限时解释范围并取得授权，不因无事件把所有权限全开。
- 临时 preflight 接收器默认不分发、不收费；切到正式接收器前核对同应用其他监听者。确认切换对象后停临时服务，再验证真人事件，不同时运行两个接收器抢事件。
- 字段创建遇限流/响应未知，先列表回读，再按字段名、类型和 ID 补缺；保留单选状态及客户已有字段，不删除表重来。

## 把环境交给客户自己的 Agent

使用 [交接模板](handoff.md) 保存客户私有上下文、实际版本/提交、正式与临时服务、工作流是否启用、通过/未执行步骤、输入入口和续接位置。不要只给 GitHub 地址。客户 Agent 先读取与运行版本匹配的 Skill；main 中的候选能力不能直接覆盖现场版本。

客户可说：“请排查现有项目这条任务，先读交接记录和版本，再检查飞书、n8n、事件与供应商回执；不要重装或重新生成，先报告原因和修复计划。”

结束前逐项证明：服务可用、SKU/任务数据正确、真实人员事件、费用确认、实际生成回执、结果回写、人工审核。未执行项目明确保留，不以安装成功代替业务通过。

## 单文档指南交付

把操作与 FAQ 合并成一份文档，顺序为当前能做什么、第一次测试、日常使用、用户排障、管理员维护。每一步写入口、动作、预期结果和异常时停止点。模板见 `docs/product/FIRST_RUN_AND_AGENT_SUPPORT.md`。只读写客户授权的资源；不要因创建文档便利而自动扩大应用文档权限。

创建标题后还须验证正文、格式、访问权限和原入口指向。原生 Base 文档与普通 Docx 不是同一种对象，不猜 API token。缺少可靠写入能力时提供可复制正文并明确所需的一次人工操作。旧指南先备份，待新文档保存核对后才清理重复入口。
