# 完成、暂停或失败都要交接

用用户能理解的语言填这份表。未执行就填“未执行”，不能从 CI 或历史报告推定当前通过。

| 项目 | 本次实际结果 |
|---|---|
| 操作 | 首次部署 / 新增项目 / 续接 / 检查修复 |
| 组织、服务器、部署目录 | 精确目标，不填写秘密 |
| 项目 | 实际项目 ID 和名称 |
| 产品版本 | 当前安装版本和发行来源 |
| 服务状态 | 已回读正在运行 / 已停止 / 无法确认 |
| 飞书 | 实际 Base 链接，未创建则说明原因 |
| 日常入口 | 已验证的飞书 Base、任务表与指南文档；无需常驻员工网页 |
| 管理入口 | 本机常驻启动器（`vf-setup` / `vf-run` / `vf-agent`）与 `launchd`/`systemd` 用户服务名，或 n8n / 完整栈的受控地址与启动方式；不粘贴一次性链接 |
| 实际启用状态 | 安装、项目配置、飞书绑定与原表订阅、单次付费执行开关、后台服务逐项状态；说明临时监听器或会话连接是否已移除 |
| 安装定位 | 实际版本/源码提交、安装目录、私有计划路径或 session、工作流 ID（适用时）；只放客户私有交接 |
| 临时权限 | 实施方公钥/临时凭据/工作台或员工短期委托的归属、到期与撤销状态，区别客户自己的入口 |
| 检查结果 | 环境安装、项目配置、飞书身份、付费模型执行、真人验收五项分别记录通过/失败/未执行 |
| 凭据和备份责任人 | 由谁保管及保存方式，不列出值 |
| 下一步 | 明确剩余工作、负责者和继续入口 |

另外保存部署目录与 session 的非秘密定位信息到客户自己的私有交接文件，避免下次新增项目依赖 Agent 的聊天记忆。只写实际成功回读的字段。不在安装同事的全局配置里集中保存不同客户的凭据。

只有以下证据都具备，才能称为“该项目可开始实际使用”：当前服务健康、正确项目和真实人员接入、选定模型路线连接、真实任务回执及媒体检查、员工验收、重启恢复和明确员工入口。只通过安装与脚本审核时，称为“安装与脚本流程测试完成”。

官网 AI 方案页用于了解产品，产品页用于取得 Skill。交接时提供实际飞书 Base 链接和 CLI 续接方式；不要把临时密码输入页或尚未验收的常驻网页写成员工入口。新增项目分别核对 Base、成员与模型配置，不重装客户底座。
