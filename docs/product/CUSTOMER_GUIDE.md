# Video Factory：从安装到新项目

Video Factory 是通过 Setup Skill 和 CLI 部署到客户服务器的视频工作流系统。交付包括安装工具、后台服务和项目配置；团队默认在飞书 Base 查看资料与任务。

当前为公开测试版，固定版本和校验摘要以官网安装页及 GitHub Release 为准。a29 曾在授权云服务器完成真实飞书建表、脚本返工审核和安装续接，由助手操作同一真实账号；这不等于新版本、不同员工或独立客户验收通过。

文中的 AI 助手也叫 Agent，需要能读取文件并在授权后操作服务器；Skill 是供它执行的安装与维护说明。管理员或实施同事使用 Skill 完成安装。员工的目标工作方式是在飞书 Base 同一任务表看脚本和视频、填写意见并审核，不需要在终端审核。当前的导入与审核命令只是 Agent 协助的技术验证，不能当作员工流程。飞书多维表格也叫 Base，商品编号也叫 SKU；n8n 是服务器上负责安排任务执行的工具。

默认安装见 [统一终端向导](SETUP_RUN_USAGE.md)，安装后按 [独立验收指南](INDEPENDENT_ACCEPTANCE.md) 逐项检查；具体命令和配置文件由助手准备。

## 你会得到什么

- 安装在你的 Agent 中的 `video-factory-setup` Skill，可重复用于部署和维护。
- 安装在你的 Linux 服务器上的产品服务、PostgreSQL 和产品专用 n8n。
- 每个项目独立的商品、飞书 Base、人员、配置和任务历史。
- 一份安装交接记录：目标服务器、实际版本、项目、入口、已通过检查、剩余事项和恢复路径。

电脑只运行 Agent；产品服务运行在服务器。不同客户独立部署，同一客户可添加多个项目。产品管理员、n8n 管理身份、飞书身份和服务器登录不是同一个账号。

## 官网、安装与日常入口

[月瑀官网 AI 方案](https://www.yueyu.tech/zh/solutions/ai-workflow-models)用于了解应用场景。[Video Factory 产品页](https://www.yueyu.tech/zh/products/video-factory/)提供说明、Skill 和安装步骤，不收密码或模型 Key。安装由客户服务器上的 CLI 执行。只有无法使用私有终端时，Agent 才可打开仅本机可达的一次性秘密输入页；该页不是官网，也不绑定业务域名。

员工日常入口是项目飞书 Base 的任务表。客户自己的服务器运行任务账本、n8n 和私网 runner，账户与密钥由客户管理；新项目复用基础服务。新的原表审核候选实现可把脚本/版本及成片写回同一任务，由员工在表内退回或通过；详见[飞书原任务表审核](FEISHU_NATIVE_REVIEW.md)。**此路径仍需固定发行包与真实飞书事件验收，不能把代码存在或安装完成当成业务验收。**可选结果同步只追加另一张结果快照表，不替代任务表审核。

## 从哪里开始

从交付页面下载完整 Skill 包，交给支持自定义 Skill 和服务器操作的 Agent。已有 Skill 时直接使用，不需要每个项目重装。不要只复制 SKILL.md：references 文件也必须保留。

a31 起安装包在公开 GitHub Release 中提供，无需 GitHub 登录。按固定标签下载并核对 release.json 和 SHA256SUMS；下载受网络限制时，可由实施人员传输同一份已核验包。公开版不附带整套服务镜像，客户服务器按固定摘要从上游拉取。

## 四个入口

| 告诉 Agent | Agent 应做什么 |
|---|---|
| 第一次安装 Video Factory | 确认服务器、检查环境、取得固定发行版、安装服务、建立第一个项目 |
| 在已有服务中新增项目 | 读取原部署与版本，创建新项目配置，复用原 stack，不重装数据库和 n8n |
| 继续上次未完成的安装 | 使用原 session 和部署目录，回读状态后续接，不重新建表 |
| 排查某项目的问题 | 先只读诊断，区分服务器、飞书、模型和任务问题，再处理准确对象 |

## 准备哪些信息

Agent 应逐步询问，不要求用户先填一大份技术表：

1. 安装用途、组织和第一个项目名称；已有部署则先选现有目标。
2. 服务器连接方式和可信主机指纹；自动环境准备支持 Ubuntu 24.04 x86_64，至少 4 GiB 内存。Agent 检查并准备 Python、Docker/Compose，不要求用户先记住这些命令。
3. 商品名称、SKU、规格及事实资料。Agent 整理非秘密 SKU 文件，用户核对；无需用户手写 JSON。
4. 飞书应用、租户、提交人和审核人。人员必须核对真实用户 ID，姓名不能冒充授权。
5. 新建测试 Base 或绑定已有表；新建时不要求事先找表 ID。
6. 脚本与视频模型的账户和 SKU 参考图；当前版本支持 DeepSeek Flash 和 MiniMax H3，其他路线不显示为可用。
7. 若另外明确选择测试既有网页审核候选，才准备域名和 HTTPS；默认 CLI 与飞书路径无需这些信息。

管理员密码、App Secret 和模型 Key 默认由用户在私有终端隐藏输入；确实无法提供私有终端时，才使用 SSH 隧道转发的临时浏览器输入窗口。Agent 负责打开安全通道，不要求把密钥发到对话，也不读取用户的秘密输入框。

## 安装后怎样使用

Setup 部署服务和项目，在终端引导飞书本人授权及建表确认。完成后先在 Base 回读商品和任务，并确认员工实际访问权限。Setup 到此结束；模型、审核、结果同步和成片按任务单独验收。

当前可由 Agent 使用操作者本人飞书授权的 CLI 逐条验证任务导入。发布含 `feishu-review` 的新版本后，管理员按[飞书原任务表审核](FEISHU_NATIVE_REVIEW.md)核对应用权限，在私有终端启用 Base 订阅，再完成飞书事件配置和推送验收；员工随后只在 Base 内操作。脚本与视频请求需分别核对模型、费用账户和单次授权；退回后保留旧版本及意见。普通安装不会自动发起付费生成。真实事件送达与员工表内审核仍需逐项验收。

新生成任务与审核记录保留在客户服务器账本。管理员可单独启用 [Base 结果同步](BASE_RESULTS.md)，把状态和视频附件追加到项目的专用结果表；未启用或未通过真实 Base 验收时，不应承诺自动回写。提交状态未知时先核对回执，不自动重复请求。项目 runner 仅在私网供 n8n 调度，需另外配置和验收。

同客户新项目复用组织和部署；商品、Base、人员和模型分别配置。不要复制上个项目的业务 Key 或任务。新增项目不自动代表该项目已启用视频生产。

## 安装结束必须交接

Agent 按 Skill 的交接模板给出：确切服务器和项目、CLI/服务版本、服务是否正在运行、飞书 Base 实际链接、导入与审核方式、管理员和备份由谁保管、哪些验收已通过、哪些未执行，以及下一次续接或新增项目怎么说。

不要在交接中包含密码、API Key、个人 token、私钥和一次性管理员链接。临时实例结束测试后的保留/停止应按约定执行，不能默认为持续收费运行。

## 更新与支持

Skill 更新不等于服务器已升级。新增项目沿用当前服务兼容的固定版本；升级由管理员安排，先备份并保留回退路径。修复从状态和回执开始，不靠清库或重装消除未知状态。

遇到问题，向维护者提供脱敏的版本、阶段、错误码和复现步骤。客户自己的秘密与业务数据留在客户环境。

a31 公开包包含项目自身 wheel 和固定依赖下载清单。首次安装由同一入口从 files.pythonhosted.org 获取外部 wheel 并逐一校验 SHA-256；服务器也需能访问服务镜像源。已完整获取的依赖可离线复用，不重复下载。
