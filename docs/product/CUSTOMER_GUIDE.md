# Video Factory：从安装到新项目

Video Factory 以飞书 Base 原任务表为团队日常入口，由 Setup Skill 和 CLI 引导自托管部署。首次安装先确认运行条件与偏好，在**三条并列的一等安装路线**中选择，无需预设购买服务器或自行搭建 n8n：

1. **无 n8n 本机常驻路线（v0.3，macOS / Linux）**：不会搭 n8n、不租服务器时，跟着 Skill 在本机一键创建独立 Python 环境、SQLite 加密账本与常驻引擎（`vf-setup` / `vf-run` / `vf-agent`），支持参考图自动托管、停机增量改配置及 `launchd` / `systemd` 用户级常驻启停，详见 [本机无 n8n 常驻指南](LOCAL_BUSINESS_SETUP.md)。
2. **便携 / 已有 n8n 路线（Windows / Mac / Linux）**：保留并接入已有 Node.js、Docker 或服务器上的 n8n，或在本机安装便携 n8n，详见 [本机安装与已有 n8n 接入](PORTABLE_N8N.md)。
3. **Ubuntu 24.04 x86_64 服务器完整栈**：在客户自己的 Ubuntu 主机上通过 SSH 与固定发行包部署产品服务、PostgreSQL、n8n 与私网 Runner，详见 [统一终端向导](SETUP_RUN_USAGE.md)。

各平台前置条件、现有 n8n 边界和模型支持状态见 [平台与模型矩阵](PLATFORMS_AND_MODELS.md)；安装后按 [独立验收指南](INDEPENDENT_ACCEPTANCE.md) 逐项检查。全流程保持**环境安装、项目配置、飞书身份、付费模型执行、人工验收**五者在说明与回执中清晰分离。

当前为公开测试版，固定服务器版本和校验摘要以官网安装页及 GitHub Release 为准（a41 固定 Linux 归档未内置 v0.3 本机无 n8n 脚本，本机无 n8n 路线使用已核验的 v0.3 版本或核心 wheel）。历史受控环境验证不等于新版本、不同员工或独立客户验收通过。

文中的 AI 助手也叫 Agent，需要能读取文件并在授权后操作本机或服务器；Skill 是供它执行的安装与维护说明。管理员或实施同事使用 Skill 完成安装与配置。员工的日常工作方式是在飞书 Base 同一任务表看脚本和视频、填写意见并审核，不需要在终端审核。飞书多维表格也叫 Base，商品编号也叫 SKU。

## 你会得到什么

- 安装在你的 Agent 中的 `video-factory-setup` Skill，可重复用于一键安装、增量改配置、新增项目与故障排查。
- 所选路线对应的运行底座：本机无 n8n 独立加密账本与常驻引擎（macOS/Linux），或本机/已有 n8n 与项目工作流，或 Ubuntu 完整栈的产品服务与 PostgreSQL。
- 每个项目独立的商品、飞书 Base、人员、参考图素材、配置和任务历史。
- 一份五层分离的安装交接记录：目标本机或服务器、实际版本、项目、入口、环境安装/项目配置/飞书身份/付费执行/真人验收各自状态，以及后续续接或启停方式。

本机无 n8n 常驻路线和便携 n8n 路线均可直接运行在个人或团队电脑上；也可选择客户服务器。不同客户独立部署，同一客户可在同一底座添加多个项目。产品管理员密码、n8n 管理身份、飞书个人身份和系统登录账户彼此独立。

## 官网、安装与日常入口

[月瑀官网 AI 方案](https://www.yueyu.tech/zh/solutions/ai-workflow-models)用于了解应用场景。[Video Factory 产品页](https://www.yueyu.tech/zh/products/video-factory/)提供说明、Skill 和安装步骤，不收密码或模型 Key。安装由所选本机或服务器上的 CLI 执行。只有无法使用私有终端时，Agent 才可打开仅本机可达的一次性秘密输入页；该页不是官网，也不绑定业务域名。

员工日常入口是项目飞书 Base 的任务表。客户自己的服务器运行任务账本、n8n 和私网 runner，账户与密钥由客户管理；新项目复用基础服务。原表审核把脚本/版本及成片写回同一任务，由员工在表内退回或通过；详见[飞书原任务表审核](FEISHU_NATIVE_REVIEW.md)。**每次部署均须核对真实飞书事件与员工权限；安装完成不等于业务验收通过。**可选结果同步只追加另一张结果快照表，不替代任务表审核。

## 从哪里开始

从交付页面下载完整 Skill 包，交给支持自定义 Skill 和服务器操作的 Agent。已有 Skill 时直接使用，不需要每个项目重装。不要只复制 SKILL.md：references 文件也必须保留。

a31 起安装包在公开 GitHub Release 中提供，无需 GitHub 登录。按固定标签下载并核对 release.json 和 SHA256SUMS；下载受网络限制时，可由实施人员传输同一份已核验包。公开版不附带整套服务镜像，客户服务器按固定摘要从上游拉取。

## 四个入口

| 告诉 Agent | Agent 应做什么 |
|---|---|
| 第一次安装 Video Factory | 先询问打算走无 n8n 本机常驻、接入/安装便携 n8n 还是部署 Ubuntu 完整栈，以及飞书准备情况；确认路线后再执行安装与首个项目配置 |
| 在已有服务中新增项目 | 读取原安装目录或服务器版本，建立新项目计划与配置，复用已有本机引擎、n8n 或 stack，不重装底座 |
| 继续上次未完成的安装 | 使用原安装目录、私有计划或 session 回读状态后续接，复用已存加密凭据，不重新建表 |
| 排查某项目的问题 | 先只读诊断，区分环境、配置、飞书、模型回执和任务状态，再处理准确对象 |

## 准备哪些信息

Agent 应逐步询问，不要求用户先填一大份技术表：

1. 安装用途、组织和第一个项目名称；已有部署则先选现有目标。
2. 路线选择（macOS/Linux 无 n8n 本机常驻、本机 Node.js/Docker n8n、已有服务器 n8n、Cloud，或 Ubuntu 24.04 x86_64 服务器完整栈）与飞书准备程度。仅在选择 Ubuntu 完整栈时才需提供远程主机 SSH 连接与可信指纹。
3. 商品名称、SKU、规格及事实资料。Agent 整理非秘密 SKU 或计划文件，用户核对；无需用户手写 JSON。
4. 飞书应用、租户、提交人和审核人。人员必须核对真实用户 ID，姓名不能冒充授权。
5. 无 n8n 本机常驻路线与便携 n8n 路线绑定已有测试 Base；没有表时先由 Agent 协助准备。Ubuntu 完整栈另提供授权后新建 Base 的向导。
6. 脚本与视频模型的账户和 SKU 参考图；无 n8n 本机常驻路线支持从普通可读目录自动校验并私有托管参考图，当前本机内核与固定发行包支持 DeepSeek Flash 和 MiniMax H3（便携 n8n 扩展接口见[矩阵](PLATFORMS_AND_MODELS.md)）。

管理员密码、App Secret 和模型 Key 默认由用户在私有终端隐藏输入；确实无法提供私有终端时，才使用 SSH 隧道转发的临时浏览器输入窗口。Agent 负责打开安全通道，不要求把密钥发到对话，也不读取用户的秘密输入框。

## 安装后怎样使用

无 n8n 本机常驻路线通过 `vf-setup` 保存加密凭据、托管参考图并完成飞书本人授权与原表审核接线，再通过 `vf-run` 默认只读常驻或用 `vfctl local-service` 渲染 `launchd` / `systemd` 用户服务管理启停（停机后还可直接增量修改商品、参考图、成员或补配视频，详见 [本机无 n8n 常驻指南](LOCAL_BUSINESS_SETUP.md)）；便携向导连接 n8n 和原 Base、核对字段并导入工作流；Ubuntu 完整栈另引导飞书本人授权及建表确认。完成后先在 Base 回读商品和任务，并确认员工实际访问权限。Setup 到此结束；模型、审核、结果同步和成片按任务单独验收。

管理员可使用本人飞书授权的 CLI 逐条核对任务导入，并按[飞书原任务表审核](FEISHU_NATIVE_REVIEW.md)核对应用权限，在私有终端启用 Base 订阅，再完成飞书事件配置和推送验收；员工随后只在 Base 内操作。脚本与视频请求需分别核对模型、费用账户和单次授权；退回后保留旧版本及意见。普通安装不会自动发起付费生成。真实事件送达与员工表内审核仍需逐项验收。

新生成任务与审核记录保留在客户服务器账本。管理员可单独启用 [Base 结果同步](BASE_RESULTS.md)，把状态和视频附件追加到项目的专用结果表；未启用或未通过真实 Base 验收时，不应承诺自动回写。提交状态未知时先核对回执，不自动重复请求。项目 runner 仅在私网供 n8n 调度，需另外配置和验收。

同客户新项目复用组织和部署；商品、Base、人员和模型分别配置。不要复制上个项目的业务 Key 或任务。新增项目不自动代表该项目已启用视频生产。

## 安装结束必须交接

Agent 按 Skill 的交接模板给出：确切服务器和项目、CLI/服务版本、服务是否正在运行、飞书 Base 实际链接、导入与审核方式、管理员和备份由谁保管、哪些验收已通过、哪些未执行，以及下一次续接或新增项目怎么说。

不要在交接中包含密码、API Key、个人 token、私钥和一次性管理员链接。临时实例结束测试后的保留/停止应按约定执行，不能默认为持续收费运行。

## 更新与支持

完整栈提供脚本密钥的只读认证预检，认证拒绝时保留旧凭据；预检不生成内容，也不证明余额充足。连续管理向导在同一轮复用短期会话，结束后撤销。便携路线在 n8n 加密保存各项目凭据；续接复用原绑定，不需要重新安装。飞书本人授权和实际业务审核仍由本人完成。

Skill 更新不等于服务器已升级。新增项目沿用当前服务兼容的固定版本；升级由管理员安排，先备份并保留回退路径。冷升级或恢复会撤销旧调度凭据：服务启动后还需由管理员对原先启用调度的项目重跑 `production-setup`，核对 n8n 执行与飞书原任务状态，才能算业务恢复。修复从状态和回执开始，不靠清库或重装消除未知状态。

遇到问题，向维护者提供脱敏的版本、阶段、错误码和复现步骤。客户自己的秘密与业务数据留在客户环境。

a31 公开包包含项目自身 wheel 和固定依赖下载清单。首次安装由同一入口从 files.pythonhosted.org 获取外部 wheel 并逐一校验 SHA-256；服务器也需能访问服务镜像源。已完整获取的依赖可离线复用，不重复下载。

## 客户自己试用与维护

安装人员应交付一份合并的使用指南与常见问题，以及客户私有部署记录。按[首次测试与 Agent 排障](FIRST_RUN_AND_AGENT_SUPPORT.md)填写“现在可做 / 尚未启用 / 下一步”，每个动作给出预期结果。客户可让自己的 Codex 沿原项目排障；仅有 GitHub 地址不等于已具备服务器权限。新客户现场部署的适用范围和待验项见[本次复盘](CUSTOMER_DEPLOYMENT_LESSONS.md)。
