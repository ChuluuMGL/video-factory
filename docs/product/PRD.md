# Video Factory 产品定义

## 定位

面向有多个视频项目的运营团队及实施伙伴，提供客户自托管的视频工作流产品。与具体发布平台解耦，默认飞书 Base 与 n8n。第一版支持人工审核，不自动发布内容。

产品体验从官网产品页与完整 Setup Skill 开始。管理员把 Skill 交给 Agent；Agent 用固定版本 CLI 引导安装和维护。员工应在项目飞书 Base 的同一任务表查看脚本/成片、填写意见并审核。当前版本尚未打通该闭环；终端审核仅用于技术验证，不能作为员工入口交付。具体阶段与缺口见 [产品形态与验收边界](PRODUCT_SHAPE.md)。

## 产品架构与责任

| 层 | 所在位置 | 职责 |
|---|---|---|
| 安装指南 | 静态交付网站 | 说明价值、当前能力、准备项、Skill、版本、步骤、成果与支持 |
| 管理 Skill | 操作者的 Agent | 首次部署、新增项目、续接、诊断、备份和升级 |
| 发行与部署工具 | 客户服务器 | 获取固定版本、核验、安装、迁移和健康回读 |
| 产品服务 | 客户服务器 | 账户/权限、项目/任务版本、凭据和执行回执 |
| n8n 与 worker | 客户服务器 | 按项目组织工作流与受控模型任务 |
| 飞书 Base | 客户环境 | 同一项目任务表承载商品引用、脚本/成片版本、人工意见和审核状态；当前回写与表内审核待实现和验收 |

每个客户独立部署、账户、数据库和凭据；同客户共享底座并按项目隔离。产品账本是状态和权限依据，n8n 不是中央客户账户系统。无需由维护者托管中央业务服务器。客户账号和 Key 不集中保存在实施人员电脑。

## 四个管理入口

1. 首次部署：确认客户与主机 → 环境预检/准备 → 固定发行包 → 欢迎配置 → 管理员安全输入 → 部署 → 飞书授权 → 首个测试项目 → 交接。
2. 新增项目：读取现有部署与版本 → 新项目配置 → SKU/资料/人员/Base/模型 → 测试 → 按验收结果决定启用。不重装底座、不默认复制旧 Key。
3. 继续安装：读取原 session 与实际资源，恢复上次未完成阶段；未知创建结果先核对，不能自动重建。
4. 检查修复：识别项目与故障层 → 回读回执 → 精确修复 → 验证。程序更新、业务返工和付费重试分别处理。

## 交互与秘密

Agent 逐阶段询问非秘密信息，替用户整理结构化文件；不要求用户手写 JSON。姓名与身份、模型选择与模型接通分别验证。密码、App Secret、API Key 通过用户私有输入进入客户凭据库，不进入聊天或 Git。

首次设置管理员；同服务新增项目验证既有管理员，不重置密码。产品管理员、n8n owner、SSH 和飞书身份分别管理。员工不需要服务器权限或安装 Skill。

## 启动与验收

服务启动表示组件健康；项目启用还需要真实身份、选定模型路线、任务产物和审核结果。网页必须明确区分当前已实现能力与待完成项。未接通业务调度不得显示生产就绪。

出厂交付应包含实际版本、目标主机、服务状态、Base 链接、导入审核方式、秘密/备份责任人、通过与未执行的检查、续接和新增项目方式。断线、重复提交、未知模型结果、权限撤销和恢复必须可追溯。

## 维护与版本

新仓库作为后续产品源码；旧仓库仅保留历史。按固定 Release 安装，不能每个项目 git pull 浮动分支。Skill 升级不自动升级服务器。服务升级前备份、核对在途任务与兼容性，失败回退并读取实际状态。

网站与发行服务不可用时，客户已有服务无需依赖该网站继续运行。第一版不加入中央客户控制台、集中 Key、自动跨客户更新或自动发布。

## 产品验收标准

完整交付要求非作者仅凭指南完成首次部署和第二项目，员工提交、退回、修订和验收真实任务，重启恢复后历史和权限正确。当前实现与缺口以 STATUS.md 和 DELIVERY_ACCEPTANCE.md 为准，不能用设计目标冒充已实现。
