# 同事独立安装与业务验收

按 [产品形态](PRODUCT_SHAPE.md) 验收 Skill、所选运行环境、飞书 Base 和 n8n；固定服务器栈另验收私网 runner。官网是说明与下载入口，不是 Setup 或员工工作区。自动化检查、历史案例、本人测试和另一名员工的独立验收分别记录。

先确定验收路线，使用无生产业务的隔离目录、实例和测试 Base：

| 路线 | 准备与启动 |
|---|---|
| 便携候选：Mac / Windows / Linux 原生 | Python 3.11+、完整候选 Skill；运行 `portable_n8n.py welcome`，选择本机 Node.js；按引导检查缺少的构建工具 |
| 便携候选：Docker | 可用的 Docker Desktop 或 Engine，选择 Docker；核对本机端口与独立数据卷 |
| 便携候选：已有 n8n | 提供实例地址及私有输入的公共 API Key，选择已有实例；不重新安装或接管旧服务 |
| 固定服务器包 | Ubuntu 24.04 x86_64、可信 SSH、固定发行包和完整 Skill；按固定包 Setup 操作 |

便携步骤见[安装指南](PORTABLE_N8N.md)。Cloud SaaS 本轮跳过，不把自托管 API 测试算作 Cloud 通过。记录精确提交或发行版本、目录/实例、费用责任与结束处理。准备获授权的商品事实及参考图、测试用飞书应用和模型账户。Setup 新建独立测试 Base，不使用生产表。密钥只在私有终端隐藏输入，不发送给 Agent 聊天。

| 阶段 | 实际操作与通过依据 |
|---|---|
| 独立安装 | 非开发者取得所选路线的完整 Skill，记录固定包或候选提交。Agent 检查环境、运行相应 CLI 问答；密码与 Key 只在私有输入处填写。已有 n8n 核对原工作流保留，新装实例核对可续接；回读版本、n8n、Base、项目和交接文件。飞书及模型流程导入后保持关闭，Setup 到此结束。 |
| 日常任务 | 在 Base 核对商品、测试任务和真实人员权限。固定栈按原导入流程操作；便携路线在原行申请生成计划，由指定负责人核对并填写确认编号。记录来源、版本和真实操作人；不从可编辑人员格推断身份。 |
| 执行与审核 | 单独配置模型账户、SKU 素材和私网 runner/n8n 调度。生成脚本及版本必须写回原任务表并显示“脚本待审核”；员工在该表退回并填写意见，修订稿回表后再通过。只有经核实的当前版本可进入视频阶段；成片及“视频待审核”回到原任务表，员工在表内验收。核对操作者、版本、供应商回执、费用和视频文件。终端审核不算此项通过。 |
| 可选结果快照 | 管理员另行启用时，核对专用结果表中的脚本/状态/附件与任务表、服务器账本和视频 SHA-256 一致；失败后按原同步标识恢复，不重复付费请求。这张表不承载人工审核。 |
| 第二项目 | 同一客户新增项目，复用服务与 n8n；检查 SKU、Base、人员、模型账户、runner 凭据与历史任务不串用。 |
| 权限与恢复 | 由另一名真实员工验证允许与拒绝的操作、撤权后失效；再演练备份、冷恢复和未完成任务续接。只有一个人时，此项记“未执行”，不能模拟第二人通过。 |

逐项写明版本、时间、操作者、对象、预期、实际结果、证据和费用。结果用“通过 / 失败 / 未执行”，不记录密码、Key、个人 token 或一次性授权链接。真实模型、真人审核和内容质量分别签收；任一项失败应保存原回执，查明状态后再决定是否重试。

结束时停止测试调度，核对未完成任务和加密备份，按已授权范围处理临时服务器，并回读实例与计费状态。

## 一次完成剩余真人验收

由一位未参与开发的同事，选择其实际使用的 Mac 或 Windows 完成上述便携安装，并保存 `handoff-PROJECT.json`。随后退出系统登录、重新登录，核对 n8n 与接收器自动启动，原工作流和队列保留；这一操作由本人执行，不在正工作的电脑上自动注销。

同一次会话再使用该同事的真实飞书账号：管理员先按项目授予测试角色，验证允许操作；验证其不能确认负责人费用或访问另一项目；撤权后再次尝试并确认拒绝。扫码只完成登录，不能替代这些操作。期间先使用不含模型节点的零费用验证流程。

若另行验收真实费用链路，先生成一个具体计划并获得负责人确认，只执行一次；保存供应商结果与原行回写，不自动重试。测试结束停用临时入口并核对原环境恢复。
