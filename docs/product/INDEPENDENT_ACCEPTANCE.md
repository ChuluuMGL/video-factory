# 同事独立安装与业务验收

按 [产品形态](PRODUCT_SHAPE.md) 验收 Skill、客户服务器、飞书 Base、n8n 和私网 runner。官网是说明与下载入口，不是 Setup 或员工工作区。自动化检查、历史案例、本人测试和另一名员工的独立验收分别记录。

交付者先准备一台无生产业务的 Ubuntu 24.04 x86_64 测试服务器、可信 SSH、固定发行包和完整 Skill；记录实例 ID、费用责任与结束处理。准备获授权的商品事实及参考图、测试用飞书应用和模型账户。Setup 新建独立测试 Base，不使用生产表。密钥只在私有终端隐藏输入，不发送给 Agent 聊天。

| 阶段 | 实际操作与通过依据 |
|---|---|
| 独立安装 | 非开发者从官网取得固定 Skill/发行包；Agent 核验摘要、检查服务器、运行 CLI Setup。本人在终端设管理员密码和 App Secret，去飞书完成授权，再回终端审阅建表计划。回读 CLI 版本、服务、n8n、Base、项目和恢复位置。Setup 到此结束。 |
| 日常任务 | 在 Base 核对商品、两条测试任务和真实人员权限。Agent 使用操作者本人的飞书授权导入一条任务；核对来源记录、版本和审计人。 |
| 执行与审核 | 单独配置模型账户、SKU 素材和私网 runner/n8n 调度。生成脚本及版本必须写回原任务表并显示“脚本待审核”；员工在该表退回并填写意见，修订稿回表后再通过。只有经核实的当前版本可进入视频阶段；成片及“视频待审核”回到原任务表，员工在表内验收。核对操作者、版本、供应商回执、费用和视频文件。终端审核不算此项通过。 |
| 可选结果快照 | 管理员另行启用时，核对专用结果表中的脚本/状态/附件与任务表、服务器账本和视频 SHA-256 一致；失败后按原同步标识恢复，不重复付费请求。这张表不承载人工审核。 |
| 第二项目 | 同一客户新增项目，复用服务与 n8n；检查 SKU、Base、人员、模型账户、runner 凭据与历史任务不串用。 |
| 权限与恢复 | 由另一名真实员工验证允许与拒绝的操作、撤权后失效；再演练备份、冷恢复和未完成任务续接。只有一个人时，此项记“未执行”，不能模拟第二人通过。 |

逐项写明版本、时间、操作者、对象、预期、实际结果、证据和费用。结果用“通过 / 失败 / 未执行”，不记录密码、Key、个人 token 或一次性授权链接。真实模型、真人审核和内容质量分别签收；任一项失败应保存原回执，查明状态后再决定是否重试。

结束时停止测试调度，核对未完成任务和加密备份，按已授权范围处理临时服务器，并回读实例与计费状态。
