# 同事独立安装与业务验收

这是交付者准备和记录的流程，不让测试者探索命令。自动化回归通过后，交付者准备以下物品再约测试者。

## 交付者先准备

- 测试者可访问的[官网安装页](https://www.yueyu.tech/zh/products/video-factory/)、同版完整 Skill 和固定安装包。a31 起可匿名下载，无需 GitHub 账号或仓库授权。首次安装需访问 GitHub、PyPI 官方文件源和固定服务镜像源；依赖完整获取后可离线复用。
- 一台临时、无生产业务的 Ubuntu 24.04 x86_64 服务器及可信 SSH；记录云资源 ID、计费责任和结束处理。建议 8 GiB 内存与足够磁盘。模型只用客户授权的测试账户。
- 一个测试子域名、DNS 和有效 HTTPS 证书；记录证书续期责任。至少一名管理员、一名独立员工；权限验收需两种实际身份，不能使用同账号冒充。
- 一个虚构或获授权的 SKU，真实参考图、产品事实和需求。新 Setup 创建独立测试 Base，不复用生产表。
- 清晰的临时费用约束、允许的模型路线及失败处理；未知提交先查回执，不重复点击生成。

## 测试者看到的流程

1. 打开安装指南，选择“首次安装”，把完整 Skill 或页面提供的提示交给自己的 Agent。
2. Agent 核对服务器，准备依赖和固定发行包，打开私有输入向导。测试者输入自己的管理员密码、飞书应用信息及项目设置；密钥不发聊天。
3. 完成本人飞书授权，核对新建 Base 内容。Agent 部署员工 HTTPS 工作区，再引导完成模型与 SKU 素材配置、n8n 调度范围及有效期。
4. 员工用自己的飞书身份打开工作区，从 SKU 建一个脚本任务，核对模型与费用账户后确认。等待草稿后退回一次，填写明确意见，重新生成下一版并通过脚本审核。
5. 核对该版视频生成计划和费用账户，批准一次。等待视频，观看后提交审核，下载已通过文件。确认模型回执、两版脚本、审核意见和成片哈希对应同一任务。
6. 再建第二个项目，复用该客户服务器/n8n；不重复安装 Skill，不串用员工身份、SKU、模型账户或旧任务。
7. 退出并重新登录，重启服务，检查任务仍在；管理员撤销员工权限后原会话不能继续审核。由交付者执行备份/恢复演练，恢复后重新授权调度，未知任务不重发。

## 每项记录结果

记录版本、日期、操作者身份、测试项目、实际入口、预期与实际结果、失败位置及证据。不记录密码、Key、App Secret、一次性入口或供应商带签名下载 URL。

三个门槛分别签收：安装可独立完成；业务路线真实运行；视频质量达到约定要求。功能路径通过不能代替内容质量。未使用独立人员、真实账户或真实模型的检查必须注明 synthetic/未执行。

测试结束：确认未完成任务、保留加密备份和证据、撤销临时凭据、停止测试调度，再按照资源授权处理临时服务器，并回读实例/计费状态。
