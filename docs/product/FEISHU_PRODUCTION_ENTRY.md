# 飞书原表生产入口：开发方案

2026-10-14，[P0-4 开发任务 #35](https://github.com/ChuluuMGL/video-factory/issues/35) 的方案，**尚未启用**。固定 a35 的生成请求仍由 CLI 提交，原表审核已经完成单账号真实验收。本项继续同一产品和后端，不新增员工网页或通用工作台。用户已选择费用确认由指定负责人逐条执行。管理员仍须按具体项目绑定真实负责人；未完成绑定时不启用付费入口。

候选开发分支实现了从 SDK 已验证事件准备脚本与视频计划的零费用处理、异常写入回读，以及指定负责人对各自计划独立确认后排入现有脚本或 H3 账本的后端关口。管理员 CLI 候选支持字段预览、显式启用和暂停：`vfctl feishu-production enable|status|pause --stack-root /opt/video-factory --session /root/vf-private/customer.setup.json`。启用时可先只开放零费用计划；暂停保留表字段并使未提交计划失效。它默认关闭，视频代码仍待云端回归及真实原表验收；不能在客户表启用，也不属于固定 a35。候选代码的测试结果以对应 PR 的云端检查为准。完整关闭条件仍按下文执行。

## 员工操作

1. 在原任务表选择项目内的商品，填写创作要求，选择“申请脚本计划”。此步只准备计划，不生成内容。
2. 服务回写该任务的计划：商品与输入摘要、目标版本、模型、客户声明的费用账户、单次请求上限、有效期和确认标识。服务端保存的计划为准，编辑单元格不能修改已准备的计划。
3. 有费用权限的人核对计划后，在独立的费用确认字段明确选择“确认此计划的一次生成”。后台重新核对本人身份、角色、任务、计划及输入；核对失败停止，不能靠普通状态格放行。
4. 复用已有脚本任务账本、n8n 和私网 Runner 执行。生成脚本回原表待审；退回保留意见和版本，下一版必须准备新的计划、重新确认费用。
5. 脚本通过后，另行申请视频计划并确认一次视频费用；成片回原表审核。脚本通过不自动授权视频，视频通过不自动发布。

## 字段与旧表兼容

| 字段 | 建议类型 | 用途 |
|---|---|---|
| 商品 / SKU | 现有映射；新表可用项目 SKU 选项 | 只能选本项目已经配置的商品 |
| 创作要求 | 文本 | 与生成脚本分开，写回草稿不覆盖原要求 |
| 生产操作 | 单选 | 申请脚本计划 / 申请视频计划，不混入审核状态 |
| 生成计划 | 文本 | 人能看懂的摘要，不包含密码、Key、内部凭据引用或 token |
| 费用确认 | 单选 | 未确认 / 确认此计划的一次生成 / 确认此计划的一次视频生成，确认人另由权限策略核对；视频选项在视频流程完成前不生效 |
| 生产提示 | 文本 | 当前阶段、错误原因、是否存在未知请求及下一步 |

实际字段名、类型、选项与 ID 先从目标表回读。名称冲突、只读或不兼容字段停止，不自动改类型或覆盖客户字段。迁移先展示精确新增字段与原映射，再由管理员确认；保留旧任务、视图、审核、来源版本及历史输出。按钮/扩展能力不作为首版依赖。

新任务可由服务生成稳定任务编号，避免员工手填技术 ID。输入版本应由请求流程管理，但不能覆盖客户“来源版本”的原业务含义；新请求身份和创作要求摘要需要单独保存，兼容旧 CLI 的来源版本校验。已有任务保持原路径可回读。

## 身份和费用边界

- 只接受现有官方 SDK 已认证的记录事件；沿用绑定的应用、租户、Base、表和实际 `operator_id.open_id`。不得接受网页、普通 HTTP 或编辑人员姓名字段伪造的操作者。
- 使用现有 `FeishuBridge` 的成员和配置检查，申请、费用确认与脚本/视频审核分别判断。费用确认策略默认未启用，管理员按具体项目和实际身份显式配置；不从可编辑人员字段推导权限。
- 发起人可申请免费计划；费用确认事件必须来自项目指定且仍有效的负责人，申请者不能自行放行。本人同时担任负责人时也须单独逐条确认。审核人身份不自动赋予费用权限。
- 单次确认绑定商品、任务版本、创作要求、退回意见、模型、区域、凭据修订、素材摘要、费用账户和提交上限。任一变化使计划失效，重新准备，不偷偷换 Key、模型或素材。
- 初始上限为每个确认计划最多一次供应商提交，不自动重试。用量/预算策略随项目保存并检查；请求次数、token/时长上限与供应商账单金额分别记录，不宣称未知费用为零或估算金额为硬账单。
- 普通“脚本通过”“视频通过”只表示业务审核。付费提交必须另有当前计划和明确费用确认事件。

## 复用现有实现

| 现有组件 | 本项接入点 |
|---|---|
| `feishu_native_events.py` | 继续唯一的专用应用 SDK 连接；不再起一个抢收同应用事件的消费者 |
| `NativeReview` / `FeishuBridge` | 共用事件范围、实际身份、最新成员和配置校验；生产事件与审核事件分流 |
| 原任务表同步 | 计划摘要、状态与提示都写同一任务；实际草稿与成片仍沿用现有同步 |
| `ScriptJobs` / `VideoJobs` | 继续原有准备、确认、提交意图、回执及未知结果保护，不建立第二套模型执行账本 |
| n8n / 私网 Runner | 已授权任务继续按原调度执行，不开放公网模型接口 |

SDK 回调先持久化有界事件，再及时 ACK，后台执行权限校验和远端回读。仅处理映射字段，避免保存无关客户内容。SDK 存活、事件收到、模型回执与原表写回分别留证。

## 幂等、失败和恢复

- 重复点击或同一事件重放只回读同一个请求和原回执，不再次收费。并发请求按任务/版本互斥；计划失效不自动创建新费用许可。
- 提交前持久化原意图，沿用现有未知结果保护。提交未知、余额/认证拒绝、附件写回未知分别显示原因及可执行下一步；不清库、不删 Base、不重发未知任务。
- 计划展示写入失败或远端未回读一致时，不进入费用确认可执行态。确认时还需回读当前行及服务端计划，拒绝旧版本和计划篡改。
- 重启不重放已提交模型请求。暂停或重新启用会撤销先前启用周期的排队生产事件、计划与费用许可；早于当前计划收到的费用确认事件也不能批准它。恢复旧检查点须撤销旧费用许可和执行授权，并与原表、原供应商记录对账，不能仅凭容器健康重新收费。
- 撤权、配置变化、凭据更新、角色变化和过期均停止未提交任务。已发生/未知的供应商请求保留原标识，不能假装撤回成功。

## 验收顺序

1. 合成事件与 SQLite/PostgreSQL 测试：无费用确认、伪造/缺失身份、跨租户/项目、权限不足、错商品、过期、输入/模型/Key/素材变化、重复/并发、恢复旧检查点均不提交模型。
2. 云端真实组件、受支持固定包检查：准备计划零生成；确认只产生一条可执行意图；相邻审核流程不回归；输入提示和错误文本脱敏。
3. 经管理员确认，在现有非生产 Base 启用字段和入口。先做免费计划、失效、取消及权限拒绝，再在明确授权范围做一条真实生成和原表审核；缺少费用或权限确认时不提交。
4. 第二个真实项目和第二账号最后验证；不能用同一个账号或合成身份代替。非作者安装与日常生产另记录总时间、人工动作、开发者介入和卡点。
