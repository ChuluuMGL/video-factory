# 客户部署复盘与改进（2026-10-24）

本记录只包含通用经验和脱敏结论。首次在客户已有业务服务器、远程 Mac、全新飞书应用及第三方模型平台的组合环境中部署，暴露了此前隔离测试未充分覆盖的问题。它不是“客户完整业务已验收”的声明。

**版本边界：**公开固定版仍为 a41。本文涉及的新星数科企业版适配及 SKU 快照模块为源码候选；旧安装包不会因文档更新而自动获得这些能力。负责人费用确认、客户首次脚本/视频生成与人工审核尚未完成。

## 本次卡点、处理与保留事项

| 卡点 | 实际观察与处理 | 固化到产品 / 验收边界 |
|---|---|---|
| ToDesk 窗口切换、断开、键盘/粘贴未送达 | 鼠标动作可见不代表文字输入成功；反复要求客户重输增加往返。改用已授权 SSH 处理服务器，网页仅留给官方授权与本人输入 | [远程接管步骤](../../skills/video-factory-setup/references/customer-remote.md)；不能记录为“已输入”直到终端出现下一步或只读认证回执 |
| 客户已有网站、数据库与旧系统 | 全新 Ubuntu 的安装路径不能直接套用；实际采用独立部署目录、独立运行配置和 loopback 端口，未重启客户主机 | 先盘点，再选已有 n8n / Node.js / Docker 路线。旧系统的个案适配不代表全版本系统已支持；不替换全局运行时、原 Docker 或网站组件 |
| Workbench 首次授权与临时 SSH 登录 | 首次 Workbench 可能需要服务关联角色；客户隧道公钥与实施方临时公钥用途不同 | 权限新增由客户确认。只传公钥，独立验证主机指纹；完成后撤销实施方临时权限，保留客户自有入口 |
| 本机隧道和服务器健康混淆 | n8n 服务可用但客户浏览器入口仍依赖其 Mac 隧道；启动器的 shell 调用也曾报错 | 启动器须验证 shebang、实际 shell、端口占用及 readiness；不是让用户记复杂命令。记录电脑登录后的启动方式；不重启服务器来修本机隧道 |
| n8n API Key 与模型 Key 混淆 | 客户不知道“创建 API Key”属于哪个工具；远程输入失败不能只归因于用户复制错误 | 输入前显示服务名称、用途、准确域名、有效期及下一步。先只读验证，再替换加密配置；不输出秘密，不把 Key 写进工作流 JSON |
| 飞书字段创建触发 99991400 | 批量初始化被限流，已建字段仍存在；按现有 schema 补齐并回读，没有重建 Base | 建字段响应失败或未知先查询，再做差量修复；不把整个初始化当作可盲目重试事务。自动限流续接仍列为待补产品能力 |
| 邮箱已确认但未解析出用户 ID | 查询成功却只返回邮箱，没有用户 ID；最终通过本应用的官方人员选择器核对准确人员 | 邮箱/昵称不是成功的身份回执。先核对组织、可用范围与企业资料；不猜 ID、不扩大到全员。费用负责人须再验证真人事件 |
| Base 可编辑、订阅为 true，但接收不到事件 | 还需独立检查应用/用户身份权限、版本发布、记录变更事件、长连接及接收器。补齐后先收到程序事件，再收到真人事件 | 不能由单个绿灯判定成功，也不能断言缺某权限就是唯一根因。程序操作人不能当作客户负责人；临时接收器切换正式入口前要停用 |
| 同品牌多个模型域名导致 401 | 先前按品牌候选网址配置；检查客户实际控制台后发现企业版域名不同，纠正后复用已有加密 Key 通过认证 | Agent 应核对控制台完整地址与 API 文档，不先要求用户反复换 Key。不跨猜测域名试发 Key；把责任写成接口识别错误，不推给客户 |
| 第三方 Seedance 不能冒充官方方舟 | 增加独立 `seedance-novai` 配置，固定企业版地址、独立凭据与费用计划；关闭 `auto_asset` | 只读认证和模型列表已验证；生成、查询、回写的真实平台闭环仍待验。参数/回执合成测试不是付费生成通过 |
| SKU 关联字段在 search / GET 返回不同结构 | search 返回 `link_record_ids`，单记录 GET 返回 `record_ids`；直接混用导致解析/比较错误 | 新 `portable_catalog.py` 先取记录 ID，再用同一 GET 接口读取与复查；绑定单一 SKU，保留任务参考图，保存后再回读。真实零模型快照已通过 |
| 已同步资料可能被后续编辑改变 | 任务保存商品快照，已生成计划/执行编号的任务拒绝再次同步；写前复查状态、资料、图与编号 | 保留版本，修改商品后新建任务。复查并非原子锁，读写间仍有并发窗口；编辑期间应暂停同步，不宣称完全解决并发冲突 |
| 使用指南做成两张表不易阅读 | 已整理为一份原生文档结构及可复制正文；远程只能确认标题，正文保存仍待核对 | 客户交付一份“使用指南与常见问题”，确认正文和阅读权限后才移除旧入口；不能拿本地 Word 或空文档标题当作云端交付完成 |
| 看见流程就误以为已经能生成 | 连接/Key 认证/关闭流程导入已完成，但真实负责人费用确认及生成闭环未完成 | 交接明确“现在可做 / 未启用 / 下一步”，使用[首次测试与 Agent 排障](FIRST_RUN_AND_AGENT_SUPPORT.md)；不把所有流程一键激活 |
| 客户自己的 Codex 缺少部署上下文 | 仓库提供通用方法，但不知道实际版本、安装目录、项目/表绑定、服务与权限 | 私有交接文件保留准确定位信息；客户 Agent 按实际版本只读诊断，不拉 main 覆盖已安装服务。临时适配应有源码提交和升级路径 |

## 已落地与尚未产品化

本 PR 固化远程接管、输入/鉴权、身份与事件、首次测试、单文档交付和 Agent 排障步骤，补充可复用交接模板；包含独立企业版模型配置和 SKU 快照工作流模块及合成回归。

以下仍需单独完成，不能由文档代替实现或真人验收：

- 把 SKU 建表、关联字段和快照模块接入便携 `welcome` 及事件分发/升级流程，使用持久创建回执与逐字段限流续接；目前不是已发行的一键创建能力。
- 把本次现场的只读凭据预检、保留旧凭据和明确服务提示收敛到统一向导，并测试 401、错误域名、重定向和输入中断；不要复制客户私有 helper。
- 该客户的负责人零费用确认、真实模型生成、表内审核与回写，以及原生文档正文、独立维护接管和临时权限撤销仍待验收。
- 新模型适配须有真实生成回执后才能提升支持级别；无额度或用户暂缓时保留“未执行”，不为了补绿灯重复收费。

## 每次安装怎样回写

问题先进入脱敏 Issue：现象、版本/路线、最小复现、期望/实际结果、停止条件和验收标准。可复用故障由 PR 同时修代码、回归样例、Skill 和排障文档；不能把客户数据库或原始日志当测试夹具。通用安装口径变化再同步官网，现场账号和地址只留客户私有交接。合并、固定包发布、客户升级、客户业务验收分别记录。
