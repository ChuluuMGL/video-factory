# 安装与项目启用

本文件描述当前受控测试版的安装能力，不替代云端结果或真人验收。准确版本、来源和校验摘要以同包发行回执为准；独立用户及真实模型验收分别记录。

**后续默认交付路径已调整：**Skill/CLI 安装、飞书 Base 日常查看，不默认部署常驻员工网页。本文下方的网页与调度章节记录既有实现；其中 n8n 执行器仍与网页部署耦合，不能据此宣称无网页路径已完成。请先读 [产品形态与验收边界](PRODUCT_SHAPE.md)。

## 从空白服务器开始

自动环境准备支持 Ubuntu 24.04 x86_64 + systemd、root 管理权限。主机需至少 4 GiB 内存，磁盘还需容纳发行镜像和成片；预检会读取真实可用空间。依赖来自 Ubuntu 自身软件源：Python 3.12、venv、Docker、Compose v2。不混装不同 Docker 发行版，不卸载已有服务，不执行系统全量升级，不替客户修改防火墙。

Agent 从固定 Release 取得归档和可信 SHA256，验证后解压。包内 `bootstrap.sh --check` 输出环境差距；已授权这台服务器的安装后执行 `bootstrap.sh --apply`，可直接附带 `start.py` 的参数进入安装。重复执行复用依赖，失败保留原服务和 Setup 文件。网络/软件源不可用时明确停止，不能宣称已安装。

相关包依据：[Ubuntu Compose 包](https://packages.ubuntu.com/noble/docker-compose-v2)。已有 Docker CE 应复用其插件，不自动改成 Ubuntu Docker 包；[Docker 安装说明](https://docs.docker.com/engine/install/ubuntu/)说明了发行包冲突。

## Agent 没有私有终端时

固定包 `start.py --browser-input` 会开启仅监听服务器 loopback 的用户输入窗口。Agent 建立可信 SSH 同端口隧道，把一次性入口提供给用户；用户在自己的浏览器输入密码/App Secret。Agent 不读取输入框、不自动填入秘密、不记录页面截图中的秘密。

这个窗口运行同一个 Setup，支持准备好的非秘密 session、逐步问答、SKU JSON 数组、隐藏输入和保存退出。口令在内存中交给安装程序，不进提示回读、答案文件或命令参数。窗口限时 30 分钟，一次性解锁、同源验证、CSRF、防重复提交。需重新开窗时使用原 session；秘密不被缓存，必要时再次输入。

安装期间的飞书授权入口与员工窗口仍使用各自端口的 SSH 隧道，Agent 负责准备隧道和解释当前步骤，不能让用户猜端口或命令。

## 常驻员工工作区

域名解析到客户服务器，客户提供该域名的有效证书与私钥。安装工具核验证书名称、匹配私钥和至少 7 天有效期；证书链/DNS/实际 HTTPS 访问仍需外部回读。证书续期由客户既有证书管理器或实施方负责，替换后重新运行同一计划/应用流程重启入口。候选尚未内置 ACME 自动签发。

Agent 使用 `vfctl workspace plan` 生成确切项目、域名、证书及运行版本计划，`workspace apply --expect-plan` 部署独立 Compose 员工入口；`status` 与 `stop` 用于检查、停用。密码/私钥不是参数值，文件需绝对路径和仅所有者可读。

员工使用自己的飞书账户登录，只能看所属项目及被授予的脚本/视频审核职责。页面常驻，个人登录最多 8 小时，空闲及过期会话回收；退出或服务重启清除登录。公网只暴露 HTTPS 审核入口，不暴露管理员与 n8n。每项目可配置独立域名/端口；所有项目仍复用客户自己的 PostgreSQL/n8n。

冷备份先停员工入口，再停数据库。证书、配置随加密备份保存。恢复/升级后必须在新 stack 上重新核对域名和运行版本并应用员工入口，不使用旧目录生成的 Compose。员工入口是否已恢复需独立验收。

## 仍需验证或补齐

以上新增能力需要对应云端测试结果。SKU 生成与视频调度候选如下；真实业务验收仍单独推进。非作者首次安装、不同人员的真实授权和交付质量不可由程序冒充。指南可访问权限、测试主机与域名由交付者准备后，才安排同事执行验收。

## n8n 执行已批准的视频任务

工作区伴随服务包含仅内网可达的执行器。管理员签发项目级 `approved_execution` 凭据，将凭据保存为 n8n 的 Header Auth；`dispatch-template` 生成默认停用的工作流。启用调度前仍需核对项目、模型账户和任务授权。只读队列凭据不能提交生成，执行凭据不能登录管理员或跨项目。

每次调度最多推进一个已人工审核且已批准具体生成计划的 H3 任务。任务输入、引用素材、密钥版本或授权过期均拒绝提交；未知提交跳过并报告，已有供应商回执继续查询，成片解码合格后仍等待视频审核。备份恢复会撤销旧调度凭据和旧未用生成授权，需要重新签发/批准。

本能力补上已批准视频任务的自动推进。后续章节描述同一候选的 SKU 生成与模型配置向导；真实模型与独立人员验收通过前，不宣称生产 ready。

## SKU → 脚本 → 视频 → 审核与交付候选

候选新增固定来源 DeepSeek Flash 脚本适配器（[官方调用接口](https://api-docs.deepseek.com/api/create-chat-completion/)），产品事实、需求及前版退回意见共同进入一次请求。脚本内容作为待审草稿；未知响应不自动重试。SKU 事实不足时不能把生成文字当作产品真实声明。

`production-setup` 是 Agent 使用的第二阶段向导，可使用同一个私有浏览器输入通道。它保存本客户的脚本/视频 Key、费用账户、H3 区域和每 SKU 的素材目录/哈希；接入完整工作区后导入 n8n 项目凭据与调度流程。启用须确认短暂重启 n8n，读取工作流回执验证；授权 90 天到期，需续接向导更新凭据。此周期是当前候选的限制，不能宣称长期无人维护。

员工工作区增加从 SKU 建脚本、退回后生成新版本、审核已生成脚本、核对并批准单次 H3 视频请求、审核成片及下载。只有 submitter 身份能请求生成，相应 reviewer 身份才能审核；成员变更每次操作重新验证。n8n 推进已批准任务，视频等待审核后不能自动视为交付。视频质量和真实供应商能力仍待真实验收。

Agent 负责准备并核对非秘密素材 JSON，例：

```json
{"EXAMPLE-001":{"assets_root":"/work/example","specification":{"duration":5,"references":[{"path":"product.png","sha256":"由真实文件计算的64位SHA256"}]}}}
```

文件位于这台客户服务器 stack 的 `data/worker/example`，目录为 10001 所有者、0700，文件私有。不要上传到开发者电脑做生成；不要用模板图片冒充客户真实输入。向导只保存引用，具体提交前再验证文件与哈希。

完整非作者流程见 [独立验收](INDEPENDENT_ACCEPTANCE.md)。当前页面的“通过”状态必须以精确候选 SHA 的云端结果和真人记录为准。

生成任务和审核记录保存在客户服务器的工作区。已有飞书 Base 记录仍可导入并按来源版本审核；本候选不会自动把新生成任务或视频附件回写到飞书表格。不要把工作区成功当作 Base 字段已更新。
