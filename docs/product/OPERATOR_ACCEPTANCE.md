# 独立安装与真实验收工作单

交给一位未参与开发的同事，按官网、完整 Skill 与所选版本完成。开发者代填、合成测试和第二人只扫码登录，都不算独立验收。当前技术结果见[收尾清单](COMPLETION_WORK.md#2026-10-19-便携路线收尾)。

不要记录或回传密码、App Secret、API Key、私钥、个人 token 或一次性授权链接。真实项目标识与原始证据保留在私有交接文件。

## 开始前填写

| 项目 | 由实际操作者填写 |
|---|---|
| 操作者、日期、是否参与开发 | 待填写 |
| 安装路线 | Mac / Windows / Linux 原生、Docker、已有 n8n，或固定服务器栈 |
| 版本与来源 | 固定包版本/摘要，或完整便携 Skill 的固定源码提交；不要混用 |
| 目标环境 | 非生产电脑/主机、独立目录、端口；已有实例记录原管理方式 |
| 飞书范围 | 专用测试 Base、应用、租户；提交人、审核人、费用负责人 |
| 开始/结束时间、开发者介入次数 | 待填写 |
| 费用与重试 | 初始为零模型调用；真实生成另确认具体计划，最多一次、不自动重试 |

Cloud SaaS 本轮跳过。旧客户项目和历史服务器不自动成为本次目标；不为等待人员新建计费资源。

## 按路线安装

- **便携路线**：取得完整 Skill 及其 `scripts`，按[便携指南](PORTABLE_N8N.md)运行 `portable_n8n.py welcome`。选择当前环境、已有实例或新安装；不要因使用 Mac / Windows 就要求租 Ubuntu 服务器。已有 n8n 保留原工作流和管理方式。
- **固定服务器包**：按该固定包 `INSTALL.md` 与 Setup 在受支持的 Ubuntu 主机操作；固定服务归档是 Ubuntu 完整栈；不要把便携路线当作原生桌面完整栈。

在私有终端输入凭据。中途安全退出一次，按同一目录续接，核对已完成配置被保留；Base、凭据和工作流没有重复创建。让向导完成字段及连接检查，保存不含密钥的交接记录。模型工作流保持关闭，安装结束不自动收费。

## 同一次会话完成验收

| 阶段 | 操作及必须回读的证据 | 结果 |
|---|---|---|
| 独立安装 | 版本/摘要、实际运行环境、n8n 与飞书连接、项目定位、交接文件；无需开发者补代码或隐藏步骤 | 未执行 |
| 退出与续接 | 取消/重开向导保留原数据；已有工作流、凭据和其他项目不变 | 未执行 |
| 桌面登录启动 | 本人在允许停机时退出系统并重新登录；核对自有 n8n 和接收器自动启动，队列及配置保留。已有 n8n 按原管理方式核对 | 未执行 |
| 零费用负责人确认 | 使用不含模型节点的验证流程，真实负责人填写计划编号；SDK 身份匹配、计划只消费一次、重放不执行 | 未执行 |
| 第二账号允许操作 | 同事登录并以已授予的测试角色操作；回读真实事件及相同任务版本 | 未执行 |
| 第二账号拒绝操作 | 非负责人不能确认费用、不能访问另一项目；撤权后旧会话再次操作被拒绝 | 未执行 |
| 交接与结束 | 客户保管凭据与数据位置；停用测试入口，恢复原接收器，核对服务及未完成任务 | 未执行 |

第二账号项目放在其他检查之后。先由管理员授予约定测试角色；不要共享管理员身份或用可编辑人员格模拟真实操作人。负责人权限变更与撤销须按明确范围操作。

每个结果填写“通过 / 失败 / 未执行”，附版本、时间、实际输出、卡点及脱敏证据。仅靠开发者补步骤才完成的安装应写“需改进”，不能签成自助安装通过。Mac 和 Windows 各自记录，不能以一台代替另一平台。

## 独立的真实费用链路

这项可在现有隔离测试环境完成，不需要等待第二账号。先在原表申请一条脚本计划，核对商品事实、模型账户、最多 2048 输出 tokens、一次提交和有效期；指定负责人亲自在 Base 填写确认编号。确认前不得提交模型请求。

通过依据为：真实 SDK 事件核实负责人 → 同一计划单次消费 → 供应商真实结果 → 同一任务行脚本/版本回写 → 人工在 Base 审核。请求状态未知时先核对原回执，不重发；不改变此前已审核脚本或成片。具体账单金额单独记录，不用 token 上限冒充人民币封顶。

## 关闭条件

非作者安装、所测桌面会话、第二账号权限及真实费用链路分别签收。发布人员再核对 PR、固定包、匿名下载、Skill 与官网是否使用同一版本。原始身份、模型回执及截图留私有环境，公开仓库只放脱敏结论。
