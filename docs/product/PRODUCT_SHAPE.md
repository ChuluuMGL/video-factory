# Video Factory 产品形态与验收边界

这里定义默认交付路径；具体命令和可用功能以所安装的固定发行版为准。云端检查、真实业务与独立员工验收分别记录。

## 用户看到的产品

1. 官网产品页说明用途、案例、版本和安装方法，提供完整 Setup Skill。它不是运行中的安装向导或员工登录页。
2. 管理员或实施人员把 Skill 交给可操作客户服务器的 Agent。Agent 使用固定版本 `vfctl`，通过终端问答完成首次安装、继续安装、新增项目、诊断和升级。密码与 App Secret 在客户服务器的私有终端隐藏输入；飞书本人授权在飞书完成，回到终端核对创建或绑定计划。正常 Setup 不打开 Video Factory 网页。仅在确实没有私有 TTY 时，操作者可显式启用临时 loopback 输入页；它不绑定公开域名，用后关闭。
3. 每个客户在自己的 Linux 服务器运行产品服务、PostgreSQL 与 n8n。同客户的项目复用底座；不同客户不共用账户、数据库或模型 Key。需要自动推进已批准任务时，Agent 先执行 `vfctl runner plan`，核对摘要后执行 `runner apply --expect-plan`。runner 仅在 Docker 私网提供执行端点和受限模型出口，不需要域名或员工网页。
4. 员工在飞书 Base 查看商品、来源任务和可见结果。真实身份导入与审核由 Agent 调用项目限定的 CLI 完成，操作者本人授权并核对计划。a31 尚未自动回写生成结果；新版本可按项目显式启用结果同步，须单独验收真实 Base 权限和附件。飞书内按钮式审核与独立员工闭环仍未完成，不作为当前能力宣传。

`review-ui` 和常驻 `workspace` 是已经存在的技术实现，但不属于推荐的首次安装路径。它们在旧发行包中的存在和历史测试记录保持可查；不以域名部署或界面测试来替代飞书优先路径的验收。后续是否保留限时媒体预览，应基于真实员工验收和飞书媒体能力决定，不在本次测试中扩成独立网页产品。

旧版 `workspace` 与新 `runner` 不得同时占用同一项目的执行器别名。已有网页部署须单独规划迁移，首次安装向导不能暗中替换。runner 的 Compose 结构和自动调度须核对当前发行版的云端回执，并在目标项目另行验收。

## 域名

`www.yueyu.tech/zh/products/video-factory/` 是产品说明与 Skill 入口。CLI/Skill 安装和飞书日常操作不要求 `video.yueyu.tech`。当前临时验收服务器的该域名不得显示 Setup 密码输入页，也不能因 DNS 或证书存在就标记产品已上线。若将来有明确的员工网页需求，应单独定义、审核和验收。

## 逐项验收

| 阶段 | 可接受的证据 |
|---|---|
| 安装 | 非作者从固定发行包在空白主机通过 CLI/Skill 安装，版本、服务和回退路径回读 |
| 飞书接入 | 新测试 Base、字段、本人身份、项目成员和来源任务逐项回读；不触碰生产 Base |
| 业务执行 | 一条经授权的真实脚本与视频任务，核对模型请求、费用回执、成片摘要与下载 |
| 审核与结果 | 本人或不同员工按角色审核、退回和复核；Base 中实际可见的结果另行回读 |
| 第二项目 | 在同一客户服务中新增项目，不重装底座；权限、任务与费用隔离 |
| 对外交付 | 非作者独立安装与接管，备份恢复、故障续接；缺少真实人员时记录未执行 |

CI、Mock、健康检查、证书签发和旧项目案例分别是技术证据，不替代上述独立验收。每个阶段使用 `通过 / 失败 / 未执行` 和精确版本记录；失败后从原 session 与实际资源续接，不重复建表、重装或付费提交。
