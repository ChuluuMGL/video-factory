# 统一终端安装与接入向导

`setup-run` 把已有 Setup、安装、管理员登录和飞书应用凭据串成同一个终端流程。一个客户自己的服务器保存自己的账户、数据库、凭据和 n8n；没有中央客户管理服务器。完整审核与模型生成属于安装后的独立验收。

## 从哪里开始

在客户 Linux x86_64 服务器上，以 root 身份运行已安装的同版本 `vfctl`。Docker/Compose、已核对的 SSH 主机和完整可信 wheelhouse 仍需先准备好；CLI 可先通过 [固定发行包安装](RELEASE_USAGE.md)；本命令本身不安装 CLI、Docker 或服务器。

```sh
vfctl setup-run \
  --session /root/vf-private/customer.setup.json \
  --root /opt/video-factory \
  --wheelhouse /root/verified-release/wheels
```

`/root/vf-private` 需预先存在且仅 root 可写。原 Setup 可续用；为同一客户建立新项目，可增加 `--from-session /root/vf-private/existing.setup.json`。使用实际私有终端，密码/App Secret 由客户隐藏输入，不经 Agent 聊天、JSON 答案文件或 shell 参数。无 TTY 会拒绝，Agent 可继续使用原分阶段 JSON 接口；随包 Skill 仅协助操作，不能自动代填秘密。

## 向导步骤

1. 收集或续填组织、服务器、项目、SKU、审核人和模型意图。可选择“新建 Base”（默认）或“绑定已有 Base”；新建只填名称，此时仍未发出创建请求。SKU 模板在发行包 `templates/products.json`，先复制到私有工作目录并填写自己的商品，再输入副本绝对路径。
2. 展示声明主机、本机名称及标识摘要、安装目录、项目、SKU 数、端口、发行文件摘要和执行计划校验值。用户确认后才安装；确认前不会创建 stack 或使用密码。
3. 新安装要求两次隐藏输入管理员密码；已有安装验证密码。默认拒绝短密码、重复确认不一致、计划/主机/目录/发行变化。健康的已有安装只导入或回读当前项目，不重拉镜像和重启服务。暂停或未完成安装按原安装器续装；升级仍使用独立 `stack upgrade`，不会把安装当成升级。
4. 新建模式选择 test / production、存放文件夹（留空为本人云空间根目录）和提交人，无需预先提供 Base/表/字段 ID；绑定模式填写已有表及字段 ID。连接草稿自动保存在原 session 同目录的 `.feishu.json` 文件，可中断续填。
5. 通过服务端管理员认证后输入 App ID 和隐藏的 App Secret，确认保存到该客户加密 vault。只保存引用与应用标识到项目元数据；下次可沿用，不必反复输入。更换凭据使用新别名，旧加密条目保留，不会覆盖正在使用的密钥。
6. 终端显示飞书官方设备授权地址和短码。本人在飞书完成授权后，回到原终端核对已验证身份与完整创建/绑定计划，输入 `yes` 才执行。服务器通过私有引用解密应用密钥，个人 token 只留在本次进程内存。新建模式确认后创建并逐项回读，再保存实际 ID；绑定模式核验后保存。测试 Base 名称已带 `VF 测试 · ` 时不会再重复添加前缀。未授权、未确认或超时会明确报告待完成。
7. 重新回读绑定并结束 Setup。到项目 Base 核对实际记录；`stack-feishu-session` 只用于本人授权、导入与本地账本验证，不是员工审核。发布含 `feishu-review` 的发行包后，按[原任务表审核](FEISHU_NATIVE_REVIEW.md)另行启用并验收飞书事件、脚本和成片写回。Setup 不自动启动员工网页、模型请求或审批。

正常 Setup 不打开 Video Factory 网页或业务域名；飞书身份授权仍由本人访问飞书官方地址。`--seconds` 限制授权窗口为 1–360 秒，其中设备授权最多等待 240 秒。无法使用私有 TTY 时，可显式启用 `--browser-input`，仅在 127.0.0.1 开临时输入页并使用可信 SSH 隧道；正常终端路径不需要它。`--connection-port` 和 `--review-port` 仅兼容旧脚本，不用于默认 Setup。

## 退出与恢复

- 选择“不”、`:quit`、Ctrl+C 可在对应阶段退出，已完成配置继续保留。重新运行相同命令，重新核对计划与登录后继续。
- 应用密钥以 vault 密文保留，数据库备份必须与服务器主密钥一起恢复，沿用现有 stack 冷备/升级流程。Setup JSON、命令参数和终端输出都不包含密钥值。
- 临时管理员会话最长 15 分钟。终端授权需要的临时 token 与固定连接草稿放在该 stack 的私有输入目录，仅容器用户 10001 可读，正常结束、取消和可处理的信号退出时删除；随后只撤销本次管理员会话，不影响其他员工。
- SIGKILL、服务器断电或 Docker 故障可能中断清理。不要将这种情况记为完成；先检查服务、临时 worker 和 `data/worker/.setup-run-*`，确认窗口已停后处理本次残留目录。未知管理员登录结果按本地管理员恢复流程处理；不自动全局撤销其他人的会话。
- `DOCKER_ADDRESS_POOL_EXHAUSTED` 表示 Docker 无法再为临时 worker 分配网络。先查看 `docker network ls` 和各网络连接的容器，只清理确认无容器、可由原 Compose 重建的旧测试网络，再重试同一向导；不要改动正在使用的网络，也不要把容器启动失败记为飞书绑定成功。
- 凭据保存不证明应用权限正确，基础安装也不证明真实业务跑通。结果保留 `business_ready=false`。a32 的临时 ECS 已完成单账号真实授权与新测试 Base 回读；任务导入、独立客户安装、完整视频任务及付费路线仍须验收。安装页面与 Skill 的本版状态见发行回执。
- 已创建 Base 的续接若返回 `FEISHU_PROVISION_BASE_CHANGED`，先用创建回执中的 Base token 核对远端确为同一张表，并查看当前名称与计划名称。仅名称不符时，可由所有者将名称恢复为原计划名称，再用原 session 续接；不要删创建日志、换项目或新建 Base。若 token、表或记录有差异，应停止并人工对账。

## 云端验证范围

候选检查包含终端隐藏输入、同命令续接、飞书授权后计划确认与取消、真实容器内密钥解析和退出后临时目录清理。兼容的本机输入页另用模拟授权接口检查窗口关闭。空白服务器、n8n、私网 runner、备份恢复及离线安装在 GitHub 云端运行；是否通过以当前提交的 Actions 为准。另一名员工和付费模型任务须分别记录验收结果。

新建的权限、恢复边界和测试说明见 [自动创建 Base](BASE_CREATION.md)。
