# 统一终端安装与接入向导

`setup-run` 把已有 Setup、安装、管理员登录、飞书应用凭据和限时审核入口串成同一个终端流程。一个客户自己的服务器保存自己的账户、数据库、凭据和 n8n；没有中央客户管理服务器。

## 从哪里开始

在客户 Linux x86_64 服务器上，以 root 身份运行已安装的同版本 `vfctl`。Docker/Compose、已核对的 SSH 主机和完整可信 wheelhouse 仍需先准备好；CLI 可先通过 [固定发行包安装](RELEASE_USAGE.md)；本命令本身不安装 CLI、Docker 或服务器。

```sh
vfctl setup-run \
  --session /root/vf-private/customer.setup.json \
  --root /opt/video-factory \
  --wheelhouse /root/verified-release/wheels
```

`/root/vf-private` 需预先存在且仅 root 可写。原 Setup 可续用；为同一客户建立新项目，可增加 `--from-session /root/vf-private/existing.setup.json`。使用实际私有终端，密码/App Secret 由客户隐藏输入，不经 Agent 聊天、JSON 答案文件或 shell 参数。无 TTY 会拒绝，Agent 可继续使用原分阶段 JSON 接口；随包 Skill 仅协助操作，不能自动代填秘密。

## 向导步骤

1. 收集或续填组织、服务器、项目、SKU、审核人和模型意图。可选择“新建 Base”（默认）或“绑定已有 Base”；新建只填名称，此时仍未发出创建请求。SKU 模板在发行包 `templates/products.json`，先复制到私有工作目录并填写自己的商品，再输入副本绝对路径。
2. 展示声明主机、本机名称及标识摘要、安装目录、项目、SKU 数、端口、发行文件摘要和执行计划校验值。用户确认后才安装；确认前不会创建 stack 或使用密码。
3. 新安装要求两次隐藏输入管理员密码；已有安装验证密码。默认拒绝短密码、重复确认不一致、计划/主机/目录/发行变化。健康的已有安装只导入或回读当前项目，不重拉镜像和重启服务。暂停或未完成安装按原安装器续装；升级仍使用独立 `stack upgrade`，不会把安装当成升级。
4. 新建模式选择 test / production、存放文件夹（留空为本人云空间根目录）和提交人，无需预先提供 Base/表/字段 ID；绑定模式填写已有表及字段 ID。连接草稿自动保存在原 session 同目录的 `.feishu.json` 文件，可中断续填。
5. 通过服务端管理员认证后输入 App ID 和隐藏的 App Secret，确认保存到该客户加密 vault。只保存引用与应用标识到项目元数据；下次可沿用，不必反复输入。更换凭据使用新别名，旧加密条目保留，不会覆盖正在使用的密钥。
6. 用户同意后打开短时飞书授权与确认入口。服务器通过私有引用解密应用密钥，个人 token 仅留在窗口内存。新建模式展示名称、位置、字段、商品和测试任务，确认后创建并逐项回读，再保存实际 ID；绑定模式核验后保存。成功后窗口自动关闭，回到终端；未确认就到期会明确报告待完成。
7. 重新回读绑定。用户可选择直接启动员工审核窗口，员工以各自飞书身份登录。没有自动模型生成或自动审批。

远程浏览器使用同端口隧道，例如 `ssh -N -L 8791:127.0.0.1:8791 -L 8790:127.0.0.1:8790 user@customer-host`。默认接入 8791、审核 8790，均为回环短时端口；可用 `--connection-port` / `--review-port` 调整。`--seconds` 限制每个窗口，范围 1–360 秒。管理员一次性链接不可分享。员工与管理员窗口保持分开。

## 退出与恢复

- 选择“不”、`:quit`、Ctrl+C 可在对应阶段退出，已完成配置继续保留。重新运行相同命令，重新核对计划与登录后继续。
- 已有部署输入原管理员密码，不是在设置新密码。候选向导会在长度不符时重新提问；登录失败时保留明确提示后关闭私有窗口，不把断开连接当成保存成功。忘记原密码时先退出并走管理员恢复流程，不重新安装或重建项目。
- 候选向导在收集配置、请求密码和执行安装前检查本地 Docker 服务。`DOCKER_ENGINE_UNAVAILABLE_CHECK_SERVICE` 表示服务不可达，不表示密码错误。Agent 先检查 `systemctl status docker` 和 `docker info`，按该服务器已有授权恢复服务，再用原 session/stack 续接；无需重置密码或重建 Base。向导不会自行启动 Docker 或改变开机策略。
- 应用密钥以 vault 密文保留，数据库备份必须与服务器主密钥一起恢复，沿用现有 stack 冷备/升级流程。Setup JSON、命令参数和终端输出都不包含密钥值。
- 临时管理员会话最长 15 分钟。连接窗口需要的临时 token 与固定连接草稿放在该 stack 的私有输入目录，仅容器用户 10001 可读，正常结束、取消和可处理的信号退出时删除；随后只撤销本次管理员会话，不影响其他员工。
- SIGKILL、服务器断电或 Docker 故障可能中断清理。不要将这种情况记为完成；先检查服务、临时 worker 和 `data/worker/.setup-run-*`，确认窗口已停后删除本次残留目录。未知管理员登录结果按本地管理员恢复流程处理；不自动全局撤销其他人的会话。
- 凭据保存不证明应用权限正确，基础安装也不证明真实业务跑通。结果保留 `business_ready=false`。设备授权与脚本审核有 a26 历史真实记录；新客户独立安装、完整视频任务、付费路线与常驻 HTTPS 仍须验收。安装页面与 Skill 的本版状态见发行回执。

## 云端验证范围

候选检查包含单元权限/密文/取消/撤销验证；真实 PTY 中的新安装、隐藏密码与密钥、同命令续接、凭据复用和员工窗口；真实容器内密钥解析、退出后中继/输入目录清理，以及 a17→a18 升级/回退。浏览器检查在独立 CLI 进程内使用模拟授权接口，确认保存后实际关闭监听并退出。全部运行测试在 GitHub 云端；是否通过以当前提交 Actions 为准。

新建的权限、恢复边界和测试说明见 [自动创建 Base](BASE_CREATION.md)。
