# 产品交付检查

当前固定版本为 **0.1.0a32，MIT 开源测试版**。官网、完整 Skill、源码和安装包可匿名读取。已完成的技术检查见 [a32 云端回归](https://github.com/ChuluuMGL/video-factory/actions/runs/37562989085)；真实业务与独立人员验收尚未完成。

## 已完成的交付

| 检查 | 当前证据 |
|---|---|
| 产品与入口 | 官网安装页、GitHub 中英文介绍、四种 Agent 入口、完整 Skill |
| 公开分发 | MIT、个人署名、历史隐私审查、公开附件审查、匿名下载安装 |
| 页面 | 正式官网桌面及移动端交互、复制、下载、案例视频与产品菜单首项 |
| 安装与续接 | 空白 Ubuntu 云虚拟机、固定包安装、重复安装、安全输入、双项目合成回归 |
| 运行与恢复 | a32 云端核心回归、真实 n8n/PostgreSQL 容器、失败升级回退、冷恢复、两种 Docker 存储模式断网安装 |
| 真实飞书 | 历史 a29 真实建表、导入防重、退回修订重审；同一账号由 Agent 操作，不是 a32 真实接入验收 |

云端合成身份、历史案例和官网上线不代表当前发行版已完成真人生产验收。源码与首次固定包可公开获取，不需要给安装者 GitHub 读取权限；客户运行服务仍需自己的管理员与模型凭据。

## 当前验收待办

| 顺序 | 工作 | 完成判据 |
|---|---|---|
| 1 | 当前固定包在隔离的 Ubuntu 24.04 主机完成 Setup | 核对包摘要、终端隐藏输入、服务与 n8n 健康、版本回读；保留旧环境 |
| 2 | 真实飞书连接 | 本人授权，新建或绑定独立测试 Base；回终端确认计划，核对 Base 与项目绑定及权限 |
| 3 | 原任务表内审核 | 脚本/版本回写同一飞书任务，员工在表内退回并留意见、复核后通过；核实操作者和当前版本。视频产物与待审状态再回同一任务，员工在表内验收。终端审核不算通过；见 [#19](https://github.com/ChuluuMGL/video-factory/issues/19) |
| 4 | 真实模型业务 | 新 SKU → 真实脚本 → 表内返工和通过 → 单次视频生成 → 原任务表待审与下载；供应商回执、费用和产物对应 |
| 5 | 可选结果快照 | 显式启用后检查最小权限、另建结果表中的脚本/状态/附件写入和 SHA-256 回读；未知提交按原同步标识恢复。此表不承载审核 |
| 6 | 第二个真实项目 | 复用客户自己的服务与 n8n，独立配置及来源；任务、人员与凭据不串用 |
| 7 | 不同真实员工权限 | 各自以本人身份操作；越权拒绝、撤权后旧会话失效，不用同一人充当两个身份 |
| 8 | 同事独立安装与接管 | 非作者从官网取得 Skill 和固定包完成 CLI Setup，按交接完成备份恢复、故障处理和临时资源收尾 |

实施步骤与记录要求见 [独立验收指南](INDEPENDENT_ACCEPTANCE.md)。资料或真实身份缺失时记录具体阻塞；不得把未执行改为通过。默认 CLI/飞书路径不需要产品业务域名或员工网页。测试时新建独立 Base，不修改生产表，密钥和原始运行证据留在客户私有环境。

## 后续能力

a32 已提供可按项目显式启用的 Base 结果同步，但真实飞书权限与附件回读仍待验收，见 [工作清单](COMPLETION_WORK.md)。旧网页工作区及其 ACME/统一门户候选不属于当前默认交付路径；不以网页上线替代 CLI、飞书和私网 runner 的验收。

## 后续发行流程

PR 与手动回归默认只检查，不创建或修改 Release。新版本在 main 完成全部云端检查后，维护者显式选择创建草稿；已发布标签和附件不覆盖。待审查的隐私发现或扫描失败须先处理，公开前再核对源代码、附件和安装回执。官网文档可单独修订，但保持固定安装包与 Skill 的版本和摘要一致。
