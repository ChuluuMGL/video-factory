01 / 安装后得到什么

从一份 Skill，到你的项目空间。

A

可复用的管理入口

Skill 留在操作者的 Agent 中。以后添加项目、续接安装或检查问题，继续使用它。

自己的云端服务

准备这几样就好

  1. 一个支持 Skill 的 Agent能够读取文件，并在授权后连接服务器。
  2. 一台自己的 Linux 服务器Ubuntu 24.04 x86_64，至少 4 GiB 内存；a28 安装器可准备 Python、Docker 和 Compose。Agent 核对空间、网络和现有服务。
  3. 飞书与项目信息应用、组织、项目、商品和审核人员。新建测试表时不用提前找表 ID。
  4. 你来完成的安全输入管理员密码、App Secret 和模型 Key 在私有输入界面填写；不发进聊天。常驻员工入口另需域名和 HTTPS 证书。

03 / Agent 会怎样带你完成

每一步都知道在做什么。

  1. 01

    确认目标

    选择首次部署或已有项目，确认组织和服务器。只问当前阶段需要的信息。

  2. 02

    检查并准备环境

    Agent 读取固定版本，核验文件，检查服务器环境；存在缺项时说明解决方式。

  3. 03

    配置项目并部署

    整理商品资料、人员和模型意图。你核对计划并设置管理员密码，安装器部署服务。

  4. 04

    授权飞书并创建工作区

    选择新建测试 Base 或绑定已有表，完成应用凭据输入和本人授权，回读实际资源。

  5. 05

    配置员工入口与模型

    Agent 配置 HTTPS 员工工作区、SKU 素材和项目 n8n 调度。你核对模型账户与授权范围，密钥保存在自己的服务器。

  6. 06

    走完首个任务并交接

    从 SKU 创建脚本，退回修订并审核，再逐条授权视频生成。审核成片后下载；分别交接入口、真实结果和剩余事项。

a28 当前支持 DeepSeek Flash 脚本和 MiniMax H3 视频，其他模型尚未接入。每次生成需单独确认，安装配置本身不会花费模型额度。

04 / 项目增加以后

新增项目，
不用重装整套服务。

同一客户复用服务和 n8n，为新项目配置独立商品、Base、人员和模型。新客户或新服务器才需要部署另一套服务。

你可以这样说

“在我们现有的服务器上新增一个项目，保留已有项目。先检查当前环境，再引导我配置。”

Agent 先核对原部署，使用独立项目配置继续；不会默认复制上个项目的密钥。

日常员工不需要装 Skill。
员工处理飞书任务和审核；管理员或实施同事使用 Skill 管理安装与维护。

06 / 使用与维护

安装之后，也有清楚的路可走。

官网 AI 页面、安装指南和员工入口有什么区别？

官网 AI 页面介绍方案；这里提供产品安装指南和 Skill；安装完成后，员工使用客户自己服务器上的 HTTPS 工作区。安装指南不保存项目账户或模型密钥。一个客户可复用服务管理多个项目，不需要每增加项目就购买一个域名。

我是同事，能帮多个客户安装吗？

可以。同一份 Skill 可重复使用，每次确认客户和目标服务器。不同客户单独部署和授权，业务密钥不集中存到实施人员电脑。

安装被打断，是否需要从头开始？

不用。告诉 Agent“继续上次安装”，读取原配置和真实状态后续接。不要重新建表或清空数据来掩盖未知结果。

安装后从哪里进入？

a28 完成部署后，Agent 交付真实 Base 链接和常驻 HTTPS 员工入口。员工用自己的飞书身份登录；新生成任务与审核记录目前保存在工作区，不会自动回写 Base。a27 仍使用短时 SSH 窗口。

服务器服务和 Skill 如何升级？

分别升级。更新 Skill 不会自动改变服务器。服务升级按固定发行版进行，需要兼容检查、备份、回读和回退方案。

出了问题应该给谁什么信息？

先让 Agent 检查具体项目。需要支持时提供版本、阶段、错误码和脱敏复现步骤，不提供密码、API Key、私钥或完整敏感日志。

本版能力与下一步验收

a28 候选增加 Ubuntu 24.04 环境准备、用户私有浏览器输入和常驻 HTTPS 员工入口。页面所示固定版本由同版云端检查通过后发布。同时补齐 SKU 脚本生成、逐条授权的视频调度、返工审核和下载；真实模型、正式域名与独立真人验收仍单独记录。
