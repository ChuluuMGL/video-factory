# 安全报告 / Security reporting

**请勿在 Issue、公开评论或聊天中粘贴 API Key、密码、私钥、客户表格或原始运行日志。**

当前维护版本为 `0.1.0a31` 开源测试版，尚未承诺安全响应 SLA。

发现漏洞或疑似凭据泄露时，优先使用 [GitHub 私密漏洞报告](https://github.com/ChuluuMGL/video-factory/security/advisories/new)，也可使用与你对接的维护者或实施人员已有的私密联系渠道。只提供版本、问题类型、脱敏复现步骤和受影响范围。若没有私密联系方式，从[官网](https://www.yueyu.tech/)联系维护者申请安全报告渠道；首次联系不要附敏感内容。不要将普通公开 Issue 当作漏洞接收箱。

疑似凭据泄露应由凭据所有者核实并撤销或轮换；仅删除文件不能消除历史副本。源代码、Git 历史、Release、镜像、Actions 日志和附件都需核查。历史改写、删除证据和凭据轮换应分别授权。

安全扫描未命中不代表没有漏洞或私有信息。详见[公开发布检查](docs/product/PUBLICATION_REVIEW.md)。

---

**Do not post API keys, passwords, private keys, customer tables or raw runtime logs in issues, public comments or chat.**

The currently maintained release is the public alpha `0.1.0a31`. No security response SLA is promised.

Use [GitHub private vulnerability reporting](https://github.com/ChuluuMGL/video-factory/security/advisories/new) or your existing private contact with the maintainer or installer. Include only the version, issue category, sanitized reproduction steps and affected scope. If you have no private contact, use the [official website](https://www.yueyu.tech/) to request a secure reporting channel without attaching sensitive material. Public issues are not the reporting channel.

Credential owners should verify and revoke or rotate exposed credentials. Deleting a file does not remove historical copies. Review Git history, releases, images, Actions logs and artifacts as well as source. History rewrites, evidence deletion and credential rotation require separate authorization.

A clean automated scan is not proof of security or privacy. See the [publication review](docs/product/PUBLICATION_REVIEW.md).
